## Role

The colored block that holds the text of a conversation turn, with optional reactions pinned to its edge.

## Usage

- Show the text of a turn inside `MessageContent`
- Tell the speakers apart by variant: `default` (primary fill) for the user, `secondary` or `muted` for the other side
- Show an assistant answer that reads as a document (headings, lists, code) with `variant="ghost"`: no fill, no padding, full width
- Show a failed or refused message with `variant="destructive"`
- Make a bubble a link or a button (open a quoted message, retry) with `asChild` on `BubbleContent`
- Pin emoji reactions or a count to the bubble with `BubbleReactions`
- Stack several bubbles of one turn in a `BubbleGroup`

<!-- rule-23: generated from design-system.index.json by scripts/build-spec-choices.ts — do not edit by hand. -->

- **Choice** (`rule-23`) — Build a conversation from its family, one component per job. The scrolling thread that follows new messages: `MessageScroller`, one `MessageScrollerItem` per message. One turn of a speaker, with avatar, header and footer: `Message`, `align="end"` for the user's own turns. The text of a turn: `Bubble` inside `MessageContent`, `variant="ghost"` for an answer that reads as a document. An event nobody said (a date, a tool call, "Conversation resumed"): `Marker`, `variant="separator"` between days. A file sent or received: `Attachment`, several in an `AttachmentGroup`. Questions the assistant asks one at a time: `Questionnaire`; a form shown all at once, outside the thread: `Field`s in a `form`.

## Constraints

- **MUST** — put the text in a `BubbleContent`: the variant colors the `BubbleContent`, not the `Bubble`
- **MUST** — use one variant per side of the conversation, the same for every turn of that side
- **MUST NOT** — use `destructive` for anything but an error on that message
- **MUST** — render `BubbleContent` as a `button` or an `a` (`asChild`) when the bubble reacts to a click; a `div` with a click handler is not reachable by keyboard
- **MUST NOT** — place more than 5 reactions in one `BubbleReactions` → show a count for the rest
- **Note** — a bubble takes at most 4/5 of the thread width, a `ghost` bubble the whole width

## Dependencies

- `class-variance-authority` for the `Bubble` variants and the `BubbleReactions` position
- `Slot.Root` from `radix-ui` (used by `BubbleContent` when `asChild={true}`)
- The `cn` utility from `@/lib/utils`

## States

| State    | Description                                                                              |
| -------- | ---------------------------------------------------------------------------------------- |
| default  | `BubbleContent` filled with the variant's background and text colors                     |
| end      | `align="end"`, or inside a `Message` with `align="end"`: the bubble moves to the end     |
| hover    | A `BubbleContent` rendered as a `button` or an `a` takes the variant's hover fill        |
| focus    | A `BubbleContent` rendered as a `button` or an `a` draws the focus ring (`ring-ring/50`) |
| active   | Not applicable                                                                           |
| disabled | Not applicable; a disabled `button` rendered through `asChild` keeps its native behavior |

## Accessibility

**Pattern**: Plain content; a link or a button when `BubbleContent` is rendered through `asChild`

**Role**: `div` elements with no role. `BubbleContent` takes the role of the element it renders with `asChild` (`button`, `a`).

**Keyboard**:

| Key             | Action                                                                        |
| --------------- | ----------------------------------------------------------------------------- |
| `Tab`           | Moves to a `BubbleContent` rendered as a `button` or an `a`, and to reactions |
| `Enter`/`Space` | Activates it, natively                                                        |

**Accessible name**: The text of a clickable `BubbleContent`. A reaction button showing only an emoji or a count takes an `aria-label` ("3 people reacted with thumbs up").

**Pitfalls**:

- The variant tells the speakers apart by color only: name the speaker in `MessageHeader` (see `Message`).
- `tinted` and `destructive` fills are tints of the primary and error colors: their text keeps the 4.5:1 contrast of `text-foreground` and `text-destructive`; a custom `className` color on them does not.

## Code example

```tsx
import {
  Bubble,
  BubbleContent,
  BubbleGroup,
  BubbleReactions,
} from "@/components/ui/bubble"
import { Message, MessageContent } from "@/components/ui/message"

export default function Example() {
  return (
    <Message align="end">
      <MessageContent>
        <BubbleGroup>
          <Bubble>
            <BubbleContent>Is the meeting still at 3?</BubbleContent>
          </Bubble>
          <Bubble>
            <BubbleContent>I can move it to 4.</BubbleContent>
            <BubbleReactions aria-label="1 reaction: thumbs up">
              👍
            </BubbleReactions>
          </Bubble>
        </BubbleGroup>
      </MessageContent>
    </Message>
  )
}
```

## Cross-references

- `Message` — the turn that holds the bubbles, in its `MessageContent`
- `Marker` — an event between turns, which is not a bubble
- `Attachment` — a file sent in a turn, next to its bubbles
- `Button` — the element a clickable `BubbleContent` renders through `asChild`
