## Role

A semantic heading (h1–h4) with four visual sizes, set in the heading typeface.

## Usage

- A page title ("Sign in", "Dashboard")
- A section title inside a Card or a panel
- Subheadings in multi-step forms

## Constraints

- **MUST NOT** — skip a heading level (an `h3` under an `h1`)
- **MUST NOT** — place more than one `h1` per page
- **MUST** — only use `as` when the semantic level differs from the visual level
- **MUST NOT** — style a heading by hand: go through `level`

## Dependencies

- `class-variance-authority` for the `level` variants
- `cn` (`@/lib/utils`) to merge classes

### `Heading`

Renders `<h{level}>`, or the element chosen with `as`.

| Prop        | Type                         | Default             | Description                                                                |
| ----------- | ---------------------------- | ------------------- | -------------------------------------------------------------------------- |
| `level`     | `1 \| 2 \| 3 \| 4`           | `1`                 | Hierarchy level and visual size                                            |
| `as`        | `` `h${HeadingLevel}` ``     | auto (= `h{level}`) | Overrides the HTML tag when the semantic level differs from the visual one |
| `className` | `string`                     | —                   | Additional CSS classes                                                     |
| `...props`  | `React.ComponentProps<"h1">` | —                   | Native `<h1>` props                                                        |

### `headingVariants`

A `cva` function: returns the classes for a combination of its axes (see **Variants**), to give another element this style.

<!-- End of the generated part. -->

How `level` maps to size. The weight is `font-semibold` and the tracking
`tracking-tight` at every level; no level overrides them.

| Level | Class       | Default tag |
| ----- | ----------- | ----------- |
| 1     | `text-2xl`  | `h1`        |
| 2     | `text-xl`   | `h2`        |
| 3     | `text-lg`   | `h3`        |
| 4     | `text-base` | `h4`        |

## Accessibility

**Pattern**: Native `h1`–`h4` heading

**Role**: Renders `h{level}`; `as` allows a semantic level that differs from the visual one.

**Keyboard**:

No keyboard interaction; screen readers jump from heading to heading.

**Accessible name**: The heading text.

**Pitfalls**:

- One `h1` per page, and no skipped levels (`h2` → `h4`).
- Pick `level` for the hierarchy, and use `as` when style and structure diverge — not the other way around.

## Code example

```tsx
import { Heading } from "@/components/ui/heading"

export default function Example() {
  return (
    <>
      <Heading level={1}>Dashboard</Heading>
      <Heading level={3} as="h2">
        Recent activity
      </Heading>
    </>
  )
}
```
