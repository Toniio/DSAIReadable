## Role

The scrolling thread of a conversation: it keeps the latest message in view as messages arrive, announces them, and offers buttons to jump to either end.

## Usage

- Hold the turns of a chat, one `MessageScrollerItem` per message, in a panel of fixed height
- Follow the conversation as it streams: the viewport stays at the end while the reader is there, and stops following when they scroll up
- Open a long thread at its end (default), its start, or its last anchored message (`defaultScrollPosition` on `MessageScrollerProvider`)
- Jump to the latest message with a `MessageScrollerButton` (`direction="end"`), to the first with `direction="start"`
- Scroll to a given message from code with `useMessageScroller().scrollToMessage(id)`, and read which messages are visible with `useMessageScrollerVisibility()`

- **Choice** (`rule-23`) — Build a conversation from its family, one component per job. The scrolling thread that follows new messages: `MessageScroller`, one `MessageScrollerItem` per message. One turn of a speaker, with avatar, header and footer: `Message`, `align="end"` for the user's own turns. The text of a turn: `Bubble` inside `MessageContent`, `variant="ghost"` for an answer that reads as a document. An event nobody said (a date, a tool call, "Conversation resumed"): `Marker`, `variant="separator"` between days. A file sent or received: `Attachment`, several in an `AttachmentGroup`. Questions the assistant asks one at a time: `Questionnaire`; a form shown all at once, outside the thread: `Field`s in a `form`.

## Constraints

- **MUST** — wrap the scroller in a `MessageScrollerProvider`, which holds the scroll state its parts and hooks read
- **MUST** — nest the parts in this order: `MessageScroller` > `MessageScrollerViewport` > `MessageScrollerContent` > `MessageScrollerItem`
- **MUST** — give the scroller a bounded height (its parent sets it): it fills its parent and scrolls inside it
- **MUST** — give each `MessageScrollerItem` a stable `messageId` when code scrolls to a message or reads visibility
- **MUST** — place `MessageScrollerButton`s inside `MessageScroller`, next to the viewport: they are positioned over it
- **MUST NOT** — nest a `ScrollArea` in a `MessageScroller`, or a `MessageScroller` in a `ScrollArea`
- **Note** — `@shadcn/react` provides the behavior (following, anchors, keyboard, the `log` role); this file styles it

## Accessibility

**Pattern**: A named scrollable region holding a live log ([WAI-ARIA `log` role](https://www.w3.org/TR/wai-aria-1.2/#log))

**Role**: The viewport is a `region` named "Messages" (`UI_STRINGS.messageScroller.viewport`) and takes focus (`tabIndex=0`). The content is a `log`: a screen reader announces each message added to it, not the ones already there.

**Keyboard**:

| Key                   | Action                                                  |
| --------------------- | ------------------------------------------------------- |
| `Tab`                 | Moves to the viewport, then into the messages' controls |
| `ArrowUp`/`ArrowDown` | Scrolls the viewport by a line                          |
| `PageUp`/`PageDown`   | Scrolls the viewport by a page                          |
| `Home`/`End`          | Scrolls to the first or the last message                |
| `Enter`/`Space`       | On a `MessageScrollerButton`: jumps to its end          |

**Accessible name**: The viewport is named by `UI_STRINGS.messageScroller.viewport`; pass `aria-label` to name it after the conversation. The button's visually hidden text is `UI_STRINGS.messageScroller.scrollToEnd` or `scrollToStart`; `children` replace it.

**Pitfalls**:

- A streamed answer is added to the log once and then grows: the log announces the first words only. Announce the finished answer through a `role="status"` region when it matters.
- An inactive button stays mounted: the styles hide it (`opacity-0`, `pointer-events-none`) and `@shadcn/react` takes it out of the tab order (`tabIndex=-1`). An element passed through `render` must forward the `tabIndex` it receives, or a hidden button takes focus.

## Code example

```tsx
import {
  MessageScroller,
  MessageScrollerButton,
  MessageScrollerContent,
  MessageScrollerItem,
  MessageScrollerProvider,
  MessageScrollerViewport,
} from "@/components/ui/message-scroller"
import { Bubble, BubbleContent } from "@/components/ui/bubble"
import { Message, MessageContent } from "@/components/ui/message"

const messages = [
  { id: "1", from: "assistant", text: "How can I help?" },
  { id: "2", from: "user", text: "Where is my order?" },
] as const

export default function Example() {
  return (
    <div className="h-96">
      <MessageScrollerProvider>
        <MessageScroller>
          <MessageScrollerViewport>
            <MessageScrollerContent>
              {messages.map((m) => (
                <MessageScrollerItem key={m.id} messageId={m.id}>
                  <Message align={m.from === "user" ? "end" : "start"}>
                    <MessageContent>
                      <Bubble
                        variant={m.from === "user" ? "default" : "secondary"}
                      >
                        <BubbleContent>{m.text}</BubbleContent>
                      </Bubble>
                    </MessageContent>
                  </Message>
                </MessageScrollerItem>
              ))}
            </MessageScrollerContent>
          </MessageScrollerViewport>
          <MessageScrollerButton />
        </MessageScroller>
      </MessageScrollerProvider>
    </div>
  )
}
```
