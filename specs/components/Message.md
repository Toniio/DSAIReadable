## Role

One turn of a conversation: who speaks, with an optional avatar, a header, the content and a footer, aligned to the start or the end of the thread.

## Usage

- Show one turn of a chat between a user and an assistant, or between people
- Put the user's own turns on the other side with `align="end"`
- Hold the speaker's `Bubble`s in `MessageContent`
- Show the speaker's name or the time in `MessageHeader`, and a status ("Read", "Edited") or actions in `MessageFooter`
- Group consecutive turns of one speaker in a `MessageGroup`

<!-- rule-23: generated from design-system.index.json by scripts/build-spec-choices.ts — do not edit by hand. -->

- **Choice** (`rule-23`) — Build a conversation from its family, one component per job. The scrolling thread that follows new messages: `MessageScroller`, one `MessageScrollerItem` per message. One turn of a speaker, with avatar, header and footer: `Message`, `align="end"` for the user's own turns. The text of a turn: `Bubble` inside `MessageContent`, `variant="ghost"` for an answer that reads as a document. An event nobody said (a date, a tool call, "Conversation resumed"): `Marker`, `variant="separator"` between days. A file sent or received: `Attachment`, several in an `AttachmentGroup`. Questions the assistant asks one at a time: `Questionnaire`; a form shown all at once, outside the thread: `Field`s in a `form`.

## Constraints

- **MUST** — put the text of a turn in a `Bubble` inside `MessageContent`, never directly in `Message`
- **MUST** — give every turn of the same speaker the same `align`: `start` for the others, `end` for the user
- **MUST** — name the speaker in `MessageHeader` or with an `Avatar` that has a text fallback when more than two people take part
- **MUST NOT** — nest a `Message` in another `Message`
- **Note** — `MessageAvatar` sits at the bottom of the turn and moves up above a `MessageFooter`; it holds an `Avatar`, it does not replace it

## Accessibility

**Pattern**: Plain content inside the conversation log (`MessageScrollerContent`, `role="log"`)

**Role**: `div` elements with no role; the log that holds them announces each new turn.

**Keyboard**:

No interaction of its own; the controls it holds (a `Button` in `MessageFooter`, a link in a `Bubble`) behave natively.

**Accessible name**: None. The speaker is read from `MessageHeader` or from the `Avatar` text fallback; a turn whose speaker is shown only by its side (`align`) is not identified for a screen reader.

**Pitfalls**:

- The side of a turn (`align`) is visual only: a screen reader does not tell the user's turns from the assistant's. Name the speaker in `MessageHeader`, or with visually hidden text (`sr-only`) at the start of `MessageContent`.
- An avatar image without `AvatarFallback` text names nobody.

## Code example

```tsx
import {
  Message,
  MessageAvatar,
  MessageContent,
  MessageFooter,
  MessageHeader,
} from "@/components/ui/message"
import { Avatar, AvatarFallback } from "@/components/ui/avatar"
import { Bubble, BubbleContent } from "@/components/ui/bubble"

export default function Example() {
  return (
    <div className="flex flex-col gap-4">
      <Message>
        <MessageAvatar>
          <Avatar>
            <AvatarFallback>AI</AvatarFallback>
          </Avatar>
        </MessageAvatar>
        <MessageContent>
          <MessageHeader>Assistant</MessageHeader>
          <Bubble variant="secondary">
            <BubbleContent>Your order ships tomorrow.</BubbleContent>
          </Bubble>
        </MessageContent>
      </Message>
      <Message align="end">
        <MessageContent>
          <MessageHeader>You</MessageHeader>
          <Bubble>
            <BubbleContent>Thanks, can I change the address?</BubbleContent>
          </Bubble>
          <MessageFooter>Read</MessageFooter>
        </MessageContent>
      </Message>
    </div>
  )
}
```
