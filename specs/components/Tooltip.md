## Role

A small contextual label that appears when a trigger is hovered or focused, built on Radix Tooltip.

## Usage

- Describe what an icon button with no visible label does
- Show the keyboard shortcut of an action (with a nested `Kbd`)
- Explain what an icon or an abbreviation means
- Add a short complement of information to an interactive element
- Show a short preview when hovering a link or a truncated element

<!-- rule-21: generated from design-system.index.json by scripts/build-spec-choices.ts — do not edit by hand. -->

- **Choice** (`rule-21`) — Pick the surface from how much it blocks and how long its content is. A blocking decision (confirm, destroy): `AlertDialog`. A short task with no inner scrolling: `Dialog`. Long content or side context: `Sheet` from `md` up, `Drawer` below — **unless** it is side navigation, which stays a `Sheet` at every width (this is what `Sidebar` does below `md`). Anchored, non-blocking content with no scrolling and at most 3 fields: `Popover`. An informative preview on hover, from `md` up: `HoverCard`. A one-line, non-interactive label of at most 80 characters: `Tooltip`.

## Constraints

- **MUST NOT** — contain interactive elements (links, buttons) → use `Popover`
- **MUST NOT** — exceed one line or 80 characters of text
- **MUST NOT** — be the only place critical information appears
- **MUST** — place a `TooltipProvider` higher in the tree, for example in the root layout
- **MUST NOT** — sit directly on a `disabled` element, which receives neither focus nor hover: wrap the element in a `<span tabIndex={0}>` that carries the trigger

## Dependencies

- `radix-ui` — the `Tooltip` primitive (Provider, Root, Trigger, Content, Portal, Arrow)
- The `cn` utility from `@/lib/utils`

## Accessibility

**Pattern**: [Tooltip](https://www.w3.org/WAI/ARIA/apg/patterns/tooltip/) (Radix Tooltip)

**Role**: `role="tooltip"`; the tooltip describes the trigger (`aria-describedby`).

**Keyboard**:

| Key                  | Action            |
| -------------------- | ----------------- |
| Focus on the trigger | Shows the tooltip |
| `Escape`             | Hides it          |

**Accessible name**: A tooltip describes; it does not name: an icon-only button keeps its `aria-label` even with a tooltip.

**Pitfalls**:

- No essential information and no interactive content in a tooltip.
- A `disabled` button does not receive focus: its tooltip is out of keyboard reach.
- The content must stay visible while the pointer is over the tooltip itself (WCAG 1.4.13): do not shorten the delays.

## Code example

```tsx
import {
  Tooltip,
  TooltipContent,
  TooltipProvider,
  TooltipTrigger,
} from "@/components/ui/tooltip"
import { Button } from "@/components/ui/button"
import { Kbd } from "@/components/ui/kbd"
import { CopyIcon } from "@phosphor-icons/react"

export default function Example() {
  return (
    <TooltipProvider>
      <Tooltip>
        <TooltipTrigger asChild>
          <Button variant="ghost" size="icon" aria-label="Copy">
            <CopyIcon />
          </Button>
        </TooltipTrigger>
        <TooltipContent>
          Copy <Kbd>⌘C</Kbd>
        </TooltipContent>
      </Tooltip>
    </TooltipProvider>
  )
}
```

- `Popover` — the alternative for interactive content
