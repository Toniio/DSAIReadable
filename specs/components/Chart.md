## Role

A container and a set of helpers for data visualization, built on `recharts`: theming, tooltips and a legend, all configured through a `ChartConfig` object.

## Usage

- Draw bar, line, area or pie charts from structured data
- Show a contextual tooltip when hovering a data point
- Show a legend that describes the data series
- Apply the theme's colors (light / dark) to the series automatically through `ChartConfig`
- Wrap a `recharts` chart in a responsive container

## Constraints

- **MUST NOT** — present raw data meant to be read value by value → use `Table`
- **MUST** — pass `ChartContainer` a `config` with at least one entry
- **Note** — in `ChartConfig`, `theme` takes precedence over `color`
- **MUST** — read a series' color from the `--color-<key>` variable that `ChartStyle` injects for each `config` key (`fill="var(--color-revenue)"`); it is not a token: its value comes from `config`
- **MUST** — give a series' `color` in `config` as a semantic variable, `var(--color-chart-1)`, not the shadcn alias `var(--chart-1)`: the alias resolves once, on `:root`, so a chart inside a nested `.dark` subtree keeps its light colors
- **MUST NOT** — nest `ChartContainer`s: one container per chart
- **MUST** — name the chart on the Recharts element, not on `ChartContainer`: `<BarChart accessibilityLayer aria-label="Revenue by month">`. The label reaches the focusable `<svg role="application">`; on `ChartContainer`, a `div` with no role, `aria-label` names nothing
- **MUST** — give the chart a visible text summary of what it shows (its takeaway); give its data as a visible `Table` too when readers need the values, under a disclosure such as `Collapsible` if the screen is short on room
- **MUST NOT** — hide a `Table` in `sr-only`: its scroll container then scrolls with nothing focusable in it (axe `scrollable-region-focusable`). Use a visible `Table`, or no table and the text summary
- **MUST** — set `rootTabIndex={-1}` on a `<Pie>`: its layer is a second tab stop, and the chart surface already is one
- **MUST NOT** — remove `ChartContainer`'s focus ring, or draw the focus of the chart another way: the container draws it while the chart has keyboard focus

## Accessibility

**Pattern**: SVG chart (Recharts) — no APG pattern

**Role**: An SVG drawn by Recharts with its accessibility layer on (the default): the surface is a focusable `application`, named by the `aria-label` of the chart element. The tooltip appears on hover and, from the keyboard, on the data point the arrow keys reach.

**Keyboard**:

| Key                        | Action                                                                                                                      |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `Tab` / `Shift+Tab`        | Moves focus to the chart and away from it; `ChartContainer` shows its ring on every focus, with or without a `ChartTooltip` |
| `ArrowLeft` / `ArrowRight` | Moves the tooltip and its cursor to the previous / next data point; the first one is shown when the chart receives focus    |
| `Enter`                    | Hides or shows the tooltip of the current data point                                                                        |

Everything the tooltip shows must also be in the text summary or the data table: a pointer user hovers, a keyboard user steps through the points, and neither is asked to find a value only the tooltip holds.

**Accessible name**: `aria-label` on the Recharts element (`BarChart`, `LineChart`, `PieChart`…) says what the chart shows; a visible title and a text summary of its takeaway sit next to it.

**Pitfalls**:

- Provide the data in another form as well (a visible text summary, a visible `Table`): a screen reader does not read bars. A chart with no `ChartTooltip` is still a tab stop where nothing changes but the ring; turn the layer off with `accessibilityLayer={false}` only when a table gives the same data.
- Categorical palette: the series stay distinct under color blindness (`npm run tokens:lint-chart`), but back the colors up with a legend or labels (see `specs/foundations/color.md`).

## Code example

```tsx
import {
  ChartContainer,
  ChartTooltip,
  ChartTooltipContent,
  type ChartConfig,
} from "@/components/ui/chart"
import { BarChart, Bar, XAxis } from "recharts"

const config: ChartConfig = {
  revenue: {
    label: "Revenue",
    color: "var(--color-chart-1)",
  },
}

const data = [
  { month: "Jan", revenue: 186 },
  { month: "Feb", revenue: 305 },
  { month: "Mar", revenue: 237 },
]

export default function Example() {
  return (
    <div className="flex flex-col gap-2">
      <ChartContainer config={config} className="min-h-52 w-full">
        <BarChart accessibilityLayer aria-label="Revenue by month" data={data}>
          <XAxis dataKey="month" />
          <Bar dataKey="revenue" fill="var(--color-revenue)" />
          <ChartTooltip content={<ChartTooltipContent />} />
        </BarChart>
      </ChartContainer>
      <p className="text-xs text-muted-foreground">
        Revenue peaked in February at 305, after 186 in January.
      </p>
    </div>
  )
}
```
