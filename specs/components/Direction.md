## Role

A context provider that passes the reading direction (LTR / RTL) down to every child component.

## Usage

- Wrap the app or a section to support right-to-left languages (Arabic, Hebrew…)
- Give the reading direction to the Radix components that depend on it (Sidebar, Tooltip, Popover…)
- Switch direction at runtime without reloading the page
- Check the RTL rendering during development

## Constraints

- **MUST NOT** — nest `DirectionProvider`s with conflicting directions
- **MUST** — place the `DirectionProvider` above every Radix component that reads the direction
- **MUST** — keep the `dir` attribute of `<html>` consistent with the `DirectionProvider`, which does not replace it
- **Note** — a utility component: it renders nothing visible
- **Note** — **The only component in the system without a `data-slot`**: it renders no DOM node of its own, so no element can carry the attribute. The exception is declared in the code with `// no-data-slot:` and checked by `npm run index:data-slot`. Target the direction through the `dir` attribute Radix sets on the consuming components

## Accessibility

**Pattern**: None — a context provider

**Role**: Renders nothing: passes `dir` (`ltr` / `rtl`) to the Radix primitives.

**Keyboard**:

No interaction; in `rtl`, the primitives reverse the horizontal arrow keys.

**Accessible name**: Not applicable.

**Pitfalls**:

- Set the `dir` (and `lang`) attribute on the document too: the provider only informs Radix components, not screen readers.

## Code example

```tsx
import { DirectionProvider } from "@/components/ui/direction"

export default function App() {
  return (
    <DirectionProvider direction="rtl">
      <div dir="rtl" lang="ar">
        {/* The application */}
        <p>Right-to-left content</p>
      </div>
    </DirectionProvider>
  )
}
```
